# こぼく工房 LINE自動返信（購入後のご案内）

こぼく工房のLINE公式アカウントで、リッチメニューの「購入後はこちら」をタップしたお客様に、
購入後の案内文と「写真を選ぶ」ボタンを自動で返信する仕組みです。

- お客様から **「購入後のご案内」** というメッセージが届いたときだけ返信します
- それ以外（通常のお問い合わせ・写真・スタンプ・友だち追加など）には **何も返信しません**
- お客様の写真・注文情報・メッセージ内容は **保存しません**
- ホームページ（Cloudflare Pages）とは別の場所（Vercel）で動くので、ホームページには影響しません
- このプログラムはリッチメニューや友だち情報を一切変更しません

## 1. ファイル構成

```
koboku-line-bot/
├─ api/
│  └─ webhook.ts        … Vercel Functions の入口（公開URL: /api/webhook）
├─ src/
│  ├─ handler.ts        … 署名の検証と「返信する・しない」の判定
│  ├─ messages.ts       … 合言葉・案内文・「写真を選ぶ」ボタンの定義 ← 文面はここ
│  └─ dedupe.ts         … 二重返信の防止
├─ test/
│  └─ webhook.test.ts   … 自動テスト（LINEには接続しません）
├─ public/
│  └─ robots.txt        … 検索エンジンに載らないようにする設定
├─ .env.example         … 環境変数のサンプル（本物の値は書かない）
├─ .gitattributes       … 改行コードの設定
├─ .gitignore           … GitHubに上げないファイルの指定
├─ .vercelignore        … Vercelに上げないファイルの指定
├─ package.json
├─ tsconfig.json
└─ vercel.json          … Vercelの設定（東京リージョンで実行）
```

### 動きの流れ

```
お客様がリッチメニュー「購入後はこちら」をタップ
   ↓ （お客様のメッセージとして「購入後のご案内」が送信される）
LINE → Vercel（/api/webhook）に通知
   ↓ ① LINEからの通知か、署名で確認
   ↓ ② 「購入後のご案内」と完全に一致するか確認
   ↓ ③ 一致したときだけ、案内文＋「写真を選ぶ」ボタンを返信
お客様が「写真を選ぶ」をタップ → LINEのカメラロールが開く → 写真は通常のトークとして届く
```

## 2. はじめる前の確認（重要）

### ① すでに他のLINE拡張ツールを使っていませんか？

Lステップ・エルメ・プロラインなど、LINE公式アカウントと連携するツールをすでに使っている場合は、
**この先の作業を進めないでください。**

- Webhook URL は1つのアカウントに **1つしか設定できません**。上書きすると、今使っているツールが動かなくなります。
- チャネルアクセストークンを **「再発行」すると、古いトークンは使えなくなります**。

LINE公式アカウントの標準機能（チャット・応答メッセージ・リッチメニュー）だけを使っている場合は、問題ありません。

### ② Vercelのプランについて

Vercelの無料プラン（Hobby）は、規約上「**非商用・個人利用のみ**」とされています。
こぼく工房は販売を行う事業のため、厳密には有料の Pro プランが対象になります。
利用するプランは、Vercelの規約（Fair use guidelines）を確認のうえ判断してください。

### ③ 作業に必要なアカウント

| サービス | 使いみち |
| --- | --- |
| LINE Official Account Manager（https://manager.line.biz/） | 応答設定・リッチメニュー |
| LINE Developers コンソール（https://developers.line.biz/console/） | 鍵の取得・Webhook設定 |
| GitHub（https://github.com/） | プログラムの置き場所 |
| Vercel（https://vercel.com/） | プログラムを動かす場所 |

> 画面のボタン名は、各サービスの更新で少し変わることがあります。見当たらないときは近い名前のものを探してください。

## 手順A：LINEの「鍵」を2つ用意する

用意するのは **チャネルシークレット** と **チャネルアクセストークン** の2つです。
どちらもパスワードと同じ扱いです。**メール・チャット・GitHub などに貼らないでください。**

### A-1. Messaging API を有効にする（まだの場合のみ）

1. https://manager.line.biz/ にログインし、こぼく工房のアカウントを開く
2. 画面右上の **「設定」** をクリック
3. 左メニューの **「Messaging API」** をクリック
4. すでに「Channel ID」などが表示されていれば有効化済みです → **A-2 へ**
5. **「Messaging APIを利用する」** をクリック
6. 開発者情報（名前・メールアドレス）を入力（初回のみ）
7. **プロバイダー** を作成または選択する（例：`こぼく工房`）
   - ⚠️ プロバイダーは **あとから変更できません**。ご自身（こぼく工房）の名前で作成してください。
8. プライバシーポリシー・利用規約のURLは空欄のままで進めて構いません → **「OK」**

### A-2. チャネルシークレットをコピーする

1. https://developers.line.biz/console/ に、Official Account Manager と **同じLINEアカウント** でログイン
2. A-1 で選んだ **プロバイダー** をクリック
3. こぼく工房の **Messaging API チャネル** をクリック
4. **「チャネル基本設定」** タブを開く
5. 下の方にある **「チャネルシークレット」** の値をコピーして、メモ帳に一時的に貼っておく

### A-3. チャネルアクセストークンを発行する

1. 同じチャネルの **「Messaging API設定」** タブを開く
2. いちばん下の **「チャネルアクセストークン（長期）」** を探す
3. **「発行」** をクリック → 表示された長い文字列をコピーして、メモ帳に一時的に貼っておく
   - すでに文字列が表示されている場合は、それをそのままコピーします（**「再発行」は押さない**）

## 手順B：GitHubにアップロードする

このフォルダは、すでに Git の準備（最初のコミット）まで済んでいます。

### B-1. GitHubに空のリポジトリを作る

1. https://github.com/new を開く
2. **Repository name**：`koboku-line-bot`
3. 公開範囲は **「Private」** を選ぶ（⚠️ Public にしない）
4. 「Add a README file」などのチェックは **入れない**
5. **「Create repository」** をクリック

### B-2. パソコンからアップロードする

1. VS Code で `koboku-line-bot` フォルダを開く
2. メニューの **「ターミナル」→「新しいターミナル」** をクリック
3. 次の2行を、1行ずつ貼り付けて Enter（`tono3679-creator` の部分はご自身のGitHubユーザー名）

```powershell
git remote add origin https://github.com/tono3679-creator/koboku-line-bot.git
git push -u origin main
```

4. ブラウザでGitHubのログイン画面が出たら、ログインして許可する
5. GitHubのページを再読み込みして、ファイルが並んでいれば成功

> `.env` などの秘密情報のファイルは `.gitignore` で除外しているので、アップロードされません。

## 手順C：Vercelにデプロイする

### C-1. プロジェクトを作る

1. https://vercel.com/ にログイン
2. 右上の **「Add New…」→「Project」** をクリック
3. 「Import Git Repository」の一覧から **`koboku-line-bot`** の **「Import」** をクリック
   - 一覧に出てこないときは **「Adjust GitHub App Permissions」** をクリックし、`koboku-line-bot` へのアクセスを許可する
4. **Framework Preset** は **「Other」** のまま
5. Build / Output の設定は **何も変更しない**

### C-2. 環境変数（鍵）を登録する

同じ画面の **「Environment Variables」** を開き、次の2つを登録します。

| Key（名前） | Value（値） |
| --- | --- |
| `LINE_CHANNEL_SECRET` | 手順A-2 でコピーしたチャネルシークレット |
| `LINE_CHANNEL_ACCESS_TOKEN` | 手順A-3 でコピーしたチャネルアクセストークン |

1. Key に `LINE_CHANNEL_SECRET`、Value に値を貼り付けて **「Add」**
2. Key に `LINE_CHANNEL_ACCESS_TOKEN`、Value に値を貼り付けて **「Add」**
3. **「Deploy」** をクリックし、完了（1分ほど）を待つ

登録が終わったら、メモ帳に貼った鍵は **保存せずに閉じてください**。

### C-3. 公開URLを確認する

1. **「Continue to Dashboard」** をクリック
2. **「Domains」** に表示されている `〇〇〇.vercel.app` を確認する（例：`koboku-line-bot.vercel.app`）
3. ブラウザで次のURLを開く

```
https://〇〇〇.vercel.app/api/webhook
```

4. `koboku-line-bot webhook is running.` と表示されれば成功です

**この `https://〇〇〇.vercel.app/api/webhook` が Webhook URL です。** 次の手順で使います。

> ⚠️ `koboku-line-bot-abc123-xxxx.vercel.app` のような **長いURLは使わないでください**。
> デプロイごとの確認用URLで、ログインが必要なためLINEからは届きません。

### あとから環境変数を直した場合

Vercelの **「Settings」→「Environment Variables」** で修正できます。
**修正しただけでは反映されません。** **「Deployments」→ いちばん上の行の「…」→「Redeploy」** を必ず実行してください。

## 手順D：LINE DevelopersでWebhookを設定する

1. https://developers.line.biz/console/ → プロバイダー → こぼく工房のチャネルを開く
2. **「Messaging API設定」** タブを開く
3. **「Webhook設定」** の **「Webhook URL」** にある **「編集」** をクリック
   - ⚠️ すでに別のURLが入っている場合は、他のツールが使用中です。**上書きせずに作業を中止**してください
4. 手順C-3 のURL（`https://〇〇〇.vercel.app/api/webhook`）を貼り付けて **「更新」**
5. **「検証」** をクリック → **「成功」** と表示されることを確認
   - 失敗する場合は「[エラーが出たときの確認方法](#エラーが出たときの確認方法)」へ
6. **「Webhookの利用」** をオン（緑）にする
7. **「Webhookの再送」** は **オフのまま**（初期設定のまま）
8. **「エラーの統計情報」** はオンにしておくと、不具合の調査に役立ちます（任意）

## 手順E：LINE Official Account Managerの応答設定を確認する

Webhook（自動返信）と、チャット（人による返信）は **同時に使えます**。

### E-1. 応答設定

1. https://manager.line.biz/ → こぼく工房のアカウント → 右上の **「設定」**
2. 左メニューの **「応答設定」** をクリック
3. 次のとおりになっているか確認する

| 項目 | 設定 | 理由 |
| --- | --- | --- |
| チャット | **オン** | お問い合わせに、これまでどおり人が返信するため |
| Webhook | **オン** | 自動返信のプログラムに通知を届けるため（手順Dの「Webhookの利用」と連動） |
| あいさつメッセージ | 今のまま | このプログラムは友だち追加時には何もしません |
| 応答メッセージ | 今のまま | 下の E-2 で重複だけ確認します |

### E-2. 既存の応答メッセージと重複させない

このプログラムが返信するのは「購入後のご案内」だけです。
Official Account Manager の「応答メッセージ」が同じ言葉に反応すると、**返信が2通届いてしまいます**。

1. Official Account Manager の **ホーム** → 左メニュー **「自動応答」→「応答メッセージ」** を開く
2. 一覧を見て、次のものがないか確認する

| 見つかったもの | 対応 |
| --- | --- |
| キーワードが **「購入後のご案内」** の応答メッセージ | **オフ** にする（プログラムと重複するため） |
| キーワードが「購入後はこちら」など別の言葉の応答メッセージ | そのままで重複しません。手順Gでリッチメニューを切り替えたあと不要になればオフに |
| **一律応答**（キーワードなし・すべてのメッセージに返信）がオン | 「購入後のご案内」にも反応して2通届きます。オフにするか、2通届いてよいかを判断 |
| 上記のどれもない | 何もしなくてOK |

## 手順F：実機テスト（リッチメニュー変更の前に）

**リッチメニューを変更する前に**、ご自身のスマートフォンで動作を確認します。
（リッチメニューは「購入後のご案内」という文字を送るだけなので、手で入力しても同じ動きになります）

スマートフォンのLINEで、こぼく工房のトークを開いて確認します。

| # | やること | 正しい結果 |
| --- | --- | --- |
| 1 | `購入後のご案内` と入力して送信 | 案内文と補足の2通が届き、画面下に **「写真を選ぶ」** ボタンが出る |
| 2 | 「写真を選ぶ」をタップ | LINEのカメラロール（写真の選択画面）が開く。ブラウザは開かない |
| 3 | 写真を選んで送信 | 写真がトークに送信される。**自動返信は来ない** |
| 4 | 続けて別の写真を、入力欄の写真マークから送信 | 送信できる。**自動返信は来ない** |
| 5 | `こんにちは` と送信 | このプログラムからの返信は来ない（応答メッセージを設定している場合は今までどおり） |
| 6 | `購入後のご案内をお願いします` と送信 | 返信は来ない（完全に一致したときだけ反応するため） |
| 7 | Official Account Manager の **「チャット」** を開く | 1〜6 のメッセージと写真が届いている |
| 8 | チャット画面から手動で返信 | スマートフォンに届く |

補足：

- 「写真を選ぶ」ボタンは **スマートフォン版LINEのみ** 表示されます（パソコン版LINEには出ません）。
- ボタンは、写真を送るか、新しいメッセージが届くと消えます。
- プログラムからの自動返信は、Official Account Manager のチャット画面には表示されないことがあります（お客様には届いています）。
- お客様の写真は、今までどおり Official Account Manager のチャット画面で確認・保存します。チャットの写真には保存期間があるため、早めに保存してください。

## 手順G：リッチメニューを設定する

手順Fのテストがすべて問題なければ、最後にリッチメニューを切り替えます。
変更するのは **「購入後はこちら」ボタンをタップしたときの動作だけ** です（画像やほかのボタンは変えません）。

1. https://manager.line.biz/ → こぼく工房のアカウント → **ホーム**
2. 左メニュー **「トークルーム管理」→「リッチメニュー」** をクリック
3. 一覧から、**現在表示中のリッチメニューのタイトル** をクリック（編集画面が開く）
4. **「コンテンツ設定」** の **「アクション」** で、「購入後はこちら」のボタンにあたる枠（A・B・C…）を探す
   - どの枠かは、左側のプレビュー画像の A・B・C の位置で確認できます
5. その枠の **「タイプ」** を **「テキスト」** に変更
6. 入力欄に、次の文字を **そのままコピーして貼り付け**（前後に空白を入れない）

```
購入後のご案内
```

7. **「保存」** をクリック
8. スマートフォンでトークを開き直し、**「購入後はこちら」** をタップ
9. 自分の発言として「購入後のご案内」が送信され、案内文と「写真を選ぶ」ボタンが届けば完成です

> リッチメニューの変更が反映されるまで、少し時間がかかることがあります。
> 反映されないときは、トーク画面を一度閉じて開き直してください。

## エラーが出たときの確認方法

### まず見る場所：Vercelのログ

1. https://vercel.com/ → `koboku-line-bot` プロジェクト
2. 上部の **「Logs」** タブをクリック
3. スマートフォンから `購入後のご案内` を送信し、新しい行が出るか見る
4. 行をクリックすると、`[koboku-line-bot]` で始まるメッセージが読めます

> 無料プランではログは **約1時間** で消えます。不具合を再現した直後に確認してください。
> ログには件数とエラー内容だけを記録し、お客様のメッセージ内容やユーザーIDは記録しません。

### ログの意味

| ログの内容 | 意味 |
| --- | --- |
| `購入後のご案内を返信しました` | 正常に返信できた |
| `受信 1件 / 返信 0件` | 通知は届いたが、合言葉と一致しないので何もしなかった（正常） |
| `署名の検証に失敗した…` | チャネルシークレットが違う、またはLINE以外からのアクセス |
| `環境変数 … が設定されていません` | Vercelに鍵が登録されていない、または登録後に再デプロイしていない |
| `返信に失敗しました … status=401` | チャネルアクセストークンが違う／再発行されて無効になった |
| `返信に失敗しました … status=400` | 応答トークンの期限切れ・使用済みなど（`body=` に理由が出ます） |
| `再送イベントのため返信しません` | 「Webhookの再送」で届いた通知（二重返信防止のため意図的に無視） |

### 症状から探す

| 症状 | 確認すること |
| --- | --- |
| 「検証」が失敗する（401） | `LINE_CHANNEL_SECRET` の値が正しいか（別のチャネルのものではないか）。直したら **Redeploy** |
| 「検証」が失敗する（500） | 環境変数が2つとも登録されているか。登録後に **Redeploy** したか |
| 「検証」が失敗する（404） | URLの末尾が `/api/webhook` になっているか |
| 「検証」が失敗する（401でログに何も出ない） | デプロイごとの長いURLを使っていないか（手順C-3の短いURLを使う） |
| タップしても何も返ってこない／Vercelのログに何も出ない | 手順Dの「Webhookの利用」、手順Eの「Webhook」がオンか |
| ログに `受信 1件 / 返信 0件` と出る | リッチメニューのテキストが `購入後のご案内` と完全に同じか（空白・誤字） |
| 返信が2通（同じ内容や別の内容）届く | 手順E-2の応答メッセージと重複していないか |
| 「写真を選ぶ」ボタンが出ない | スマートフォン版LINEか。LINEアプリが最新か |
| 通常のお問い合わせがチャットに届かない | 手順E-1の「チャット」がオンか |

### LINE側で確認する

- LINE Developers →「Messaging API設定」→ **「検証」** ボタン：Vercelまで通知が届くかをいつでも確認できます
- 「エラーの統計情報」をオンにしている場合：LINE Developers のチャネルの **「統計情報」** タブで、Webhookの送信エラーを確認できます

### いったん止めたいとき

LINE Developers →「Messaging API設定」→ **「Webhookの利用」をオフ** にすると、自動返信はすぐ止まります。
（チャットや応答メッセージなど、ほかの機能には影響しません。リッチメニューのボタンは、もとの動作に戻してください）

---

## 文面を変えたいとき

`src/messages.ts` を編集します。

| 変えたいもの | 編集する場所 |
| --- | --- |
| 案内文 | `PURCHASE_GUIDE_TEXT` |
| 写真の送り方の補足（2通目） | `PHOTO_HINT_TEXT` |
| ボタンの文字 | `PHOTO_BUTTON_LABEL`（20文字まで） |
| 合言葉 | `TRIGGER_TEXT`（リッチメニュー側のテキストも同じ文字に変更する） |

編集したら、VS Code のターミナルで次を実行すると、Vercelが自動で更新します（1分ほど）。

```powershell
git add -A
git commit -m "文面を変更"
git push
```

## セキュリティについて

| 項目 | 対応 |
| --- | --- |
| Webhook署名の検証 | すべてのリクエストで `x-line-signature` を検証し、合わないものは 401 で拒否します |
| 秘密情報の管理 | チャネルシークレット・アクセストークンはVercelの環境変数だけに置き、ソースコードには書いていません |
| GitHubへの流出防止 | `.env` 系のファイルは `.gitignore` で除外。リポジトリは Private で作成します |
| 二重返信の防止 | ① 同じイベントIDは2回処理しない ② 再送イベントには返信しない ③ 1回しか使えない応答トークンで返信する |
| 処理するイベントの限定 | 1対1トークの、テキスト「購入後のご案内」だけ。それ以外は読み捨てます |
| 個人情報 | 写真・注文情報・メッセージ内容・ユーザーIDを保存せず、ログにも残しません |

万一、鍵を誤って公開してしまった場合は、LINE Developers でチャネルアクセストークンを **再発行**（チャネルシークレットも再発行）し、
Vercelの環境変数を新しい値に更新して **Redeploy** してください。

## 開発者向け：自動テスト

Node.js 24 が必要です。LINEには接続せず、署名検証・返信内容・二重返信防止などを確認します。

```powershell
npm install
npm test          # 自動テスト
npm run typecheck # 型チェック
```
